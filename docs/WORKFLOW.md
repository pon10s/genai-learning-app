# WORKFLOW.md — コンテンツ生成ワークフロー（B方式の手順書）

> Claude Code（あなた）が「記事探し → 要約 → クイズ化」を行うときの正式手順。
> 先生が「今日のキャッチアップ」「クイズ作って」と言ったら、この手順に従う。

## 全体の流れ

```
1. 候補出し   … Web検索で最新の良記事を5件ほど候補提示
2. 選定       … 先生が読みたい記事を選ぶ
3. 要約       … 記事を数行で要約（前提知識として使う）
4. クイズ生成 … 4択クイズを作る（問題・選択肢・正解・解説・出典）
5. 検証       … 事実誤認チェック・出典の確認
6. 保存       … data/quizzes/ にJSONで追記
7. 記録       … CHANGELOG と PHASES を更新
```

## ステップ詳細

### 1. 候補出し
- WebSearch で、テーマ（trend / ai-dev / basics）に沿った**新しめの**記事を探す。
- 候補は「タイトル / 出典 / 日付 / なぜ学ぶ価値があるか一言」で5件ほど提示。
- 怪しい情報源・古すぎる記事は外す。一次情報・公式ブログを優先。

### 2. 選定
- 先生に番号で選んでもらう。複数可。

### 3. 要約
- 選ばれた記事を WebFetch で読み、**3〜5行**で要約。
- 専門用語は噛み砕く。新出用語は `docs/GLOSSARY.md` に追記候補としてメモ。

### 4. クイズ生成（品質ルール）
- 1記事あたり 2〜4問を目安。
- **解説が主役**。なぜ正解か／なぜ他が違うかを学びになる形で書く。
- 選択肢は紛らわしすぎず、かつ即答できすぎない難易度に。
- `category` `difficulty` `source` を必ず埋める。**出典URLは必須**。
- スキーマは REQUIREMENTS.md §5 に従う。

### 5. 検証（手戻り防止の要）
- 生成したクイズの事実が、出典記事と矛盾しないか自分で読み直す。
- 推測で断定していないか確認。不確かなら問題にしない。
- 日付・モデル名・数値は特に慎重に。

### 6. 保存
- `src/data/quizzes/` に、日付やテーマ単位のJSON（配列）として保存。
- 新規ファイルを足したら **`src/data/manifest.json` にファイル名を1行追加**（アプリが読む一覧）。
- `id` は重複しないよう `YYYY-MM-DD-テーマ-連番` 形式。
- ※ 公開サイトには `src/` 配下しか載らないため、必ず `src/data/` 内に置く。

### 7. 記録
- `CHANGELOG.md` に「何の記事から何問追加したか」を記録。
- 必要なら `docs/PHASES.md` の進行ログを更新。

## 禁止・注意

- 出典のないクイズを作らない。
- 不確かな事実を断定で出題しない（学習アプリで誤りを覚えさせない）。
- アプリ本体のコードにAI呼び出しを足さない（このワークフローは人＝Claude Codeが回す）。
