# AUTO_GENERATION.md — 毎日の自動生成ルーティン手順書

> この手順は、**スケジュール実行されるClaude（このプロジェクトの記憶を持たない別セッション）**が、
> 1日1回・自動で「新しい記事＋クイズ」を1本作って公開するための、自己完結した指示書です。
> まず `CLAUDE.md` `REQUIREMENTS.md`（§5）`docs/WORKFLOW.md` を読んでから実行すること。

## ゴール
- 最新かつ重要な生成AI情報から **記事を5本** 作り、`src/data/articles/` を**まるごと入れ替える**（古い記事は削除）→ manifest書き換え → 検証 → push。
- 「最近かつ重要」を優先（できれば直近1〜2ヶ月のニュース・重要解説）。カテゴリは分散させる。
- push されると GitHub Pages が自動デプロイし、そのまま公開される（人の確認は挟まない）。
- だからこそ **検証ゲートを必ず通す**。通らなければ push しない。
- 実装は `tools/generate-article.js`（COUNT=5 既定）。最低3本作れなければ入れ替えを中止する。

## 手順

### 1. テーマをランダムに選ぶ
- `trend`（最新トレンド）/ `ai-dev`（AI駆動開発）/ `basics`（開発の基礎）から1つをランダムに選ぶ。
- 既存記事に偏りがあれば、少ないカテゴリを優先してよい（`src/data/articles/` を確認）。

### 2. 記事を探す（おまかせ自動ランダム）
- WebSearch で、そのテーマの**新しめで信頼できる**記事を数件探す。
- 一次情報・公式ブログ・定番技術メディアを優先。怪しい情報源・広告だらけの記事は避ける。
- **既に扱った題材と重複しないこと**（`src/data/articles/` 内の既存 title / source.url を確認し、近い内容は避ける）。
- 候補の中から **1本をランダムに選ぶ**。

### 3. 本文を読む
- 選んだ記事を WebFetch で実際に読む（403等で読めなければ別候補や一次情報に差し替える）。
- 事実は**記事に書かれている内容だけ**を使う。推測で断定しない。
- 数値・モデル名・日付など時点依存の情報は「その記事の時点の主張」として扱う。

### 4. 記事ファイルを作る（スキーマは REQUIREMENTS.md §5）
- `src/data/articles/<わかりやすいslug>.json` を新規作成。`id` は `art-<slug>` で一意に（既存と重複しない）。
- 必須：`id` `category` `title` `readMinutes` `source(url必須)` `summary` `questions`。
- `summary`：**段落の配列・合計300〜500字**（1〜2分で読める、やさしい全体まとめ）。専門用語はかみ砕く。
- `questions`：**2〜3問**。**選択肢は“紛らわしい良問”**に（同分野・同粒度のダミー、ジョーク選択肢禁止、
  記事を理解していないと選べないレベル）。`explanation` で「なぜ正解か／なぜ他が違うか」を書く。

### 5. manifest に追加
- `src/data/manifest.json` の `articles` 配列に、作ったファイル名（`articles/<slug>.json`）を1行追加。

### 6. 検証ゲート（必須）
- `node tools/validate-articles.js` を実行。
- **エラーが出たら直す。通るまで push しない。** どうしても通らなければ、その回は中止（push しない）。

### 7. 公開（push）
- `git add -A`
- `git commit -m "content: 自動生成 daily記事「<title>」を追加"`（末尾に Co-Authored-By 行）
- `git push origin main`
- Pages が自動デプロイ。完了後、公開URLの `data/manifest.json` が増えていれば成功。

## やってはいけないこと
- 検証に通っていないデータを push する
- 出典のない記事を作る／不確かな事実を断定する
- 既存の記事ファイルを削除・改変する（追加のみ）
- アプリ本体のコード（app.js等）を勝手に変える（このルーティンはデータ追加だけ）

## 1回あたりの分量
- 記事は **1本だけ**。増やしすぎない。
